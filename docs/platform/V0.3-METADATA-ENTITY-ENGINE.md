# SDI One Platform Upgrade v0.3 — Metadata Entity Engine

This release adds the first true metadata-driven Entity Engine to the working 10x Operational Explorer foundation.

## What changed

### Entity Registry
Customers, Jobs, Vendors, Invoices, Invoice Lines, Equipment, and Inventory Transactions are now registered as platform entities.

Each registered entity defines:
- display name and plural name
- domain
- route path
- source Prisma model
- icon and color
- CSV/source fields
- searchable/filterable/list-visible fields
- workspace sections
- capabilities
- permission templates
- relationship rules

### New database models
- `EntityType`
- `EntityField`
- `EntityCapability`
- `EntityWorkspaceSection`
- `EntityPermissionTemplate`
- `EntityRelationshipRule`

### New pages
- `/dashboard/entities`
- `/dashboard/entities/[entityKey]`
- `/dashboard/entities/[entityKey]/workspace`
- `/dashboard/admin/entity-engine`

### New API endpoints
- `/api/entities`
- `/api/entities/[entityKey]`

### New scripts
- `npm run seed:entities`
- `npm run entities:sync`

## Setup

After pulling this release or replacing the project folder:

```powershell
npm install
npx prisma generate
npx prisma migrate dev --name entity_engine_v03
npm run seed:entities
```

If you already have imported data, you do not need to re-import. The entity engine metadata is additive.

## Why this matters

SDI One now begins moving away from hardcoded pages toward a platform model. Future modules can be introduced by defining metadata, then inheriting platform capabilities like search, relationships, timeline, documents, permissions, workspace rendering, and AI context.
